KB-08: Product Page UX Research Summary

Catalog Copilot Knowledge Base | Team-authored | v1.0, September 2026

Scope and Sources

This is our summary of free, public articles from the Baymard Institute and the Nielsen Norman Group on how shoppers read product pages. We did not use or upload any of Baymard's paid research, and nothing here is quoted at length; it is written in our own words so the GPT can apply the principles without us redistributing anyone's licensed material. The findings are general principles, not numbers, because a paraphrased statistic without the underlying study is exactly the kind of claim this project is trying to avoid.

1. Shoppers Scan Before They Read

Nielsen Norman Group's eyetracking work on web reading found that people scan in patterns, most famously an F shape, fixing on the start of lines and on the first few words of each block. On a product page that means the first words of a title and the bold label on each bullet do most of the work. The GPT should put the deciding information (size, material, the main use) at the very front of each bullet, not at the end of a sentence.

2. Descriptions Should Answer Questions, Not Sell Adjectives

Both groups report the same failure from different angles: shoppers leave or return products when the page did not answer a basic question, and the most common missing answers are dimensions, materials, and what is included. Marketing language does not substitute for that information, and in Baymard's testing shoppers tended to skip past it. This is the research reason behind the "specific over impressive" rule in KB-01.

3. Separate Highlights From Specifications

Baymard recommends keeping a short set of highlights near the top and a structured specification list further down, instead of burying specs in a paragraph. For Catalog Copilot that maps to bullets for the three to five things that drive the decision and a clean attribute list the page template can render as a table. The GPT should not cram every attribute into the bullets.

4. Make Scale Obvious

Shoppers misjudge size from photos, and that is a common source of "not as described" returns. Dimensions should be stated in the first bullet for anything where size matters, and alt text or image notes should mention scale when the image shows it (for example, a lamp next to a sofa). Where a reference object helps, the copy can use one that is concrete and common, such as "fits a standard 12-inch shelf."

5. Consistency Across Products

Pages that use the same structure for every product in a category are easier to compare. This is one of the stronger arguments for using a GPT at all: it applies the same format to the thousandth product that it applied to the first, which a team of tired merchandisers does not always manage.

6. How the GPT Should Use This File

  • Use it to decide order and structure: which bullet goes first, what belongs in specs, where dimensions appear.

  • Cite it when a reviewer asks why a draft is structured a certain way.

  • Do not quote numbers or percentages from it; there are none, on purpose.

  • When it conflicts with KB-01 on format, KB-01 wins; this file explains the reasons, KB-01 sets the rules.
